## 2) Executive summary

Phase 2.3 is runtime-approved after a mid-cycle architectural fix. Initial implementation passed G1/G2 but failed G3 on Android 14+/15 because `createVirtualDisplay()` was called per frame on the same projection session. The capture pipeline was refactored to a persistent one-session `VirtualDisplay` + `ImageReader` model, which removed token-reuse failures and enabled stable repeated captures. Static checks stayed green (`lint`, `tsc`, `assembleDebug`) after the fix.

Runtime gates then closed with defensible outcomes: G1/G2/G3/G6/G8 passed behaviorally; G4 and G5 passed in documentation mode with explicit instrumented code paths and no regression signals; G7 was locked as a documented OEM UI constraint because Honor did not expose a usable system "Stop sharing" affordance from the active projection notification path. Overall, implementation aligns with preflight intent, with one explicit amendment: persistent capture session architecture.

## 4) Architectural patches validated (C1-C4 + persistent-session amendment)

### C1 - FGS ordering race (Android 14+ safety)

- **Intent:** ensure projection creation happens only after foreground service is truly running with mediaProjection type.
- **Implementation reference:** `ScreenshotModule` (`startCapture()`, FGS polling gate, projection creation in start path).
- **Validation gates:** G2, G3, G6, G8.

### C2 - Android 13+ notification runtime grant

- **Intent:** avoid hidden/fragile FGS behavior by requesting `POST_NOTIFICATIONS` at runtime before start.
- **Implementation reference:** `TrackingScreen` start-capture handler (`PermissionsAndroid.request(...)`).
- **Validation gates:** G2 notification visibility and stable session start.

### C3 - bitmap/memory hygiene

- **Intent:** prevent bitmap retention/leak growth in capture path.
- **Implementation reference:** `ScreenshotModule.toBitmap()` + post-compression `bitmap.recycle()`.
- **Validation gates:** G8b (heap/graphics stability during repeated captures).

### C4 - system-stop event propagation to JS

- **Intent:** ensure JS/UI state flips when projection is stopped by system callback.
- **Implementation reference:** native emit (`RN_SCREENSHOT_PROJECTION_STOPPED`) + JS listener (`onProjectionStopped`).
- **Validation gates:** G6 callback line observed; G7 constraint documented.

### Persistent-session amendment (post-G3 fix)

- **Intent:** comply with Android 14+/15 projection lifecycle by creating one `VirtualDisplay` per consent session.
- **Implementation reference:** `ScreenshotModule` session fields (`sharedReader`, `sharedVirtualDisplay`, `latestImage`) and `startCaptureSession()` / `releaseCaptureSession()`.
- **Validation gates:** G3 (strong), G8b repeated captures without token reuse errors.

## 8) Privacy and security note

- Consent remains per-session and explicit.
- Consent is cleared on system stop callback and on stop flow.
- Native module does not persist frame files by default; frame bytes are returned to JS (`bytesBase64`), and any persistence policy is JS-side responsibility.
- Foreground notification remains active while capture session is running.

---

## 9) Risks / WATCH list

- **N1 cosmetic:** programmatic stop also triggers `projection_stopped_by_system` callback (expected callback behavior).
- **N2:** retry loop can consume attempts rapidly in specific setup-missing scenarios (non-blocking, observed as acceptable current behavior).
- **OEM UI gap (Honor):** system stop affordance not practically available from notification action path.
