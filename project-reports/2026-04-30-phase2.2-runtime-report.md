### G3 — Force-stop persistence: DOCUMENTED OEM CONSTRAINT

After `adb shell am force-stop com.mobilern`, `adb shell cmd jobscheduler run -f com.mobilern <jobid>` does not persistently fire the worker on Honor / Android 15. `dumpsys jobscheduler` showed:

```
JobScheduler: isReadyToBeExecutedLocked, job is prohibit by iaware
```

Honor's `iaware` system aggressively blocks force-stopped apps. **Pragmatic substitute (Path B.1, wait-real-time)**: backgrounding via HOME button (not force-stop) + 16-min real-time wait. Within the captured window we did not observe a fire (next periodic was due outside the window), but no new `iaware` blocks were logged either. Documented as OEM platform constraint, not a code defect.

**Cross-validation**: G2 (worker functional via JS-driven one-shot) + G9 bonus (periodic fired exactly 15 min after prior fire, surviving G8 idle cycle) demonstrate the worker code, periodic schedule, and JobScheduler integration are sound. G3's failure is OEM-specific to Honor's force-stop semantics. WorkManager's design for force-stop survival is correct (`PeriodicWorkRequest` is enqueued in `androidx.work` SQLite database and re-registered on next process start); behavior on stock AOSP / Pixel is expected to be normal.

### 5.1 Cursor monotonicity primitive — single source of truth

File: `mobile-rn/android/app/src/main/java/com/mobilern/usage/SyncPrefs.java` (lines 39–44)

```java
public static void advanceCursorMonotonic(Context ctx, long incomingCursorMs) {
    SharedPreferences p = prefs(ctx);
    long saved = p.getLong(KEY_LAST_SYNC_EPOCH_MS, -1L);
    long next = Math.max(saved, incomingCursorMs);
    p.edit().putLong(KEY_LAST_SYNC_EPOCH_MS, next).apply();
}
```

Used by both Phase 1 foreground (`UsageTrackingModule.confirmSync`) and Phase 2.2 worker (`UsageSyncWorker.doWork`). `KEY_LAST_SYNC_EPOCH_MS` and `PREFS_NAME` are explicitly constrained to align with Phase 1 (lines 13–14, with comment).

public void cancelPeriodicSync(Promise promise) {

### 5.9 URL mirror primitive (JS-side)

File: `mobile-rn/src/services/usageTrackingService.ts` (lines 77–98)

```ts
export async function mirrorNativeApiBaseUrl(url: string): Promise<void> {
  if (
    Platform.OS !== 'android' ||
    !UsageTracking?.setApiBaseUrl ||
    !url?.trim()
  ) {
    return;
  }
  const normalized = url.trim().replace(/\/+$/, '');
  await UsageTracking.setApiBaseUrl(normalized);

  let hostForLog = normalized;
  try {
    const hasScheme = /^[a-z][a-z0-9+.-]*:\/\//i.test(normalized);
    const u = new URL(hasScheme ? normalized : `http://${normalized}`);
    hostForLog = u.host || normalized;
  } catch {
    // keep hostForLog as normalized
  }
  console.log('RN_USAGE_BG_JS', `url_mirror url=${hostForLog}`);
}
```

## 6. Cross-OEM portability

### Standard AOSP APIs used (portable across Android 6+)

| API | Portability | Use |
| --- | --- | --- |
| `androidx.work.WorkManager` 2.9.0 | All Android 14+ devices, AOSP guarantee | Periodic + one-shot scheduling |
| `androidx.work.PeriodicWorkRequest` + `setConstraints(NetworkType.CONNECTED, RequiresBatteryNotLow)` | AOSP standard | Battery / network constraint enforcement |
| `androidx.work.BackoffPolicy.EXPONENTIAL` (30 s initial) | AOSP standard | Failure retry policy |
| `WorkManager.cancelUniqueWork` / `enqueueUniquePeriodicWork(REPLACE)` | AOSP standard | Disable + interval-change semantics |
| `android.app.usage.UsageStatsManager` (under `PACKAGE_USAGE_STATS`) | AOSP since Lollipop | Read-only usage aggregates |
| `SharedPreferences` (`MODE_PRIVATE`, `apply()`) | AOSP universal | Cursor + URL + user-id persistence (cross-process safe) |
| OkHttp 4.x | Bundled with RN | HTTP POST to backend |

### Documented OEM caveats

| OEM | Behavior | Mitigation |
| --- | --- | --- |
| Honor (Android 15) | `iaware` blocks force-stopped apps from JobScheduler firing (G3); aggressive doze-equivalent policy on background processes | Battery whitelist as test-only aid; production parent-onboarding gesture for "allow background" |
| Xiaomi (MIUI) — *deferred* | Known to require manual battery exemption for WorkManager periodic | Same parent-onboarding pattern |
| Samsung (One UI) — *deferred* | Known to defer WorkManager more aggressively under "Sleeping apps" lists | Same |
| Stock AOSP / Pixel — *deferred* | Standard Doze + App Standby; expected to work without whitelist | Default Phase 2.2 design suffices |

### Deferred multi-device validation

Test scope for Phase 2.2 was the single Honor ALT-NX1 device. Phase 2.4 demo dry-run should ideally include at least one Pixel / AOSP device test, OR an explicit Phase 5 disclosure that "production rollout would require a 30-min smoke test on Pixel + Samsung + Xiaomi devices, not feasible in current PFE scope."

## 9. Risks / future bug seeds (WATCH list)

### 9.1 RN URL polyfill cosmetic (low)

`url_mirror url=http://localhost:3000` (scheme included). Hermes / RN `new URL(...).host` may return the full URL on this stack; native SharedPreferences value is correct. Cosmetic log artifact only.

### 9.2 `setApiBaseUrlOverride` does not immediately mirror (low / informational)

Override is set in AsyncStorage; mirror to native happens on next successful `getApiBaseUrl()` resolution. **Deliberate behavior** — failed override never overwrites known-good native URL. Document in operator runbook for Phase 2.4.

### 9.3 Honor `iaware` force-stop block (medium — UX onboarding affordance needed)

Force-stopped Honor apps are deferred from JobScheduler firing by `iaware`. Not a code defect; OEM-specific policy. Production parent-onboarding flow should include "allow background" gesture for non-stock-AOSP devices.

### 9.4 Honor JobScheduler retains `Idle contexts` after cancel / replace (low — diagnostic only)

Idle-context entries with `EXTRA_IS_PERIODIC=true` linger after `cancelUniqueWork` and `ExistingPeriodicWorkPolicy.REPLACE`. Authoritative state is `Pending queue` and `Active jobs` (both empty after cancel / replace). Diagnostic interpretation only — does not affect runtime behavior.

### 9.5 Doze deferral not strictly stress-tested (low — nice-to-have validation)

The G8 quiet idle window did not span the next periodic boundary. Periodic survived G8 cleanly per G9 evidence (fired exactly at 15-min boundary post-unforce), but a future test could explicitly hold idle across a periodic boundary to observe maintenance-window vs deferred-on-exit behavior. Current evidence is sufficient.

### 9.6 Multi-device validation deferred (medium for production, low for PFE)

Phase 2.2 was tested only on Honor ALT-NX1. Production rollout would require smoke tests on Pixel + Samsung + Xiaomi.
